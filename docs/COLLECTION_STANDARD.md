# 隐藏吃法收集标准 v2：主要餐品优先

更新：2026-10-25。用户最新要求覆盖下方历史v1中关于小料、精确风味/部位和原版完全复刻的拦截条件。

## 当前执行标准

1. 有对应吃法本身的真实配图和来源，优先实拍；素材公开权利另行处理。
2. 核验主要餐品能否获得。番茄酱等常见配料包、奶油球、糖及调味小料不要求逐项查到MCP SKU；未列出不阻断推荐。写“可选、有则加或可省略”，不作每店免费或必送承诺。
3. 允许简单替代：鸡排风味、鸡肉部位、同用途冰品等不要求与原版完全一致。保留来源原名，另写实际可配餐品与差异；口味替代不当作原图食材识别成功。替代方案可作为探索候选，不强制先取得替代版实拍，但原图须注明原版参考。
4. 原帖身份、菜单可配置、操作配方、项目试做分别标注。源文未写的数量和步骤不冒充原作者事实；需要时可给明确标作项目建议的近似操作，不把未试做写成实测。
5. 主要商品有时段或当前缺失时，说明限制或提供简易替代。当前用户明确要求移除抹茶雪冰相关两款，保留来源档案，不放入推荐；其他历史小料缺失不自动排除其无粉/简化版本。
6. 主要餐品可配置候选与完整来源证据分开统计；一店一次菜单仍只证明查询上下文，不声称全国常年有售。主食材与做法均无法识别的保留研究区，不因标准放宽就编造成完整配方。

C批最初按v2得到7个候选；用户随后授权重审三批，当前统一图库为16张去重卡（15类组合＋1项技巧）。完整46条复审与原始快照保留在本地unified-v2目录。原始批次的ready字段是历史证据状态；统一维护以统一吃法资料.json为准，不自动发布公开catalog。

## 历史v1（追溯用，冲突以以上v2和用户最新指令为准）

### 隐藏吃法收集标准 v1

生效：2026-10-24。用户要求：有隐藏吃法本身配图，有具体商品名或能可靠识别的商品，不采用时令食品，配方有可操作性。目标范围为麦当劳中国大陆；本文件是后续收集与筛选的统一规则。

## 进入可操作吃法池的必要条件

1. **对应实拍图。** 至少一张能看清这道组合成品或实际制作过程的实拍照片／真实视频截图，图片内容与配方一致；优先成品图。只有标题海报、单独原料、人物合影、另一道吃法的图不通过。实拍与 AI 示意归属不明的，先待核，不以 AI 示意充当实拍。保留作者、来源及图片类型。
2. **商品明确。** 每个关键原料要有具体商品名、必要口味和规格；同时保留来源原名与大陆对应商品字段。“某个汉堡”“冰淇淋”“酱料”不能直接当完整商品名。“双吉”等别名可以整理，但需保留对应依据。图片识别必须有清晰包装、菜单、原帖文字或同制作过程等证据可复核；仅凭外观猜测不通过。派的口味、麦满分底款和麦旋风口味不静默代换。
3. **排除时令、限时与停供商品。** 所有核心麦当劳商品均须有当前大陆常规供应依据；活动限定、季节限定、联名限定和已停供的历史商品不进入主库。海外菜单、历史文章、一家门店一次有货或名称听起来熟悉，都不足以证明常规供应。尚不能判断的标 `unknown` 并留待核；确认限时／停供的标 `excluded`，不以相似商品无声替换。更换原料必须成为单独的替代方案，并重新核配图与操作依据。
4. **拿到餐品能照做。** 说明购买份数、实际使用量或可重复的操作用量、组装顺序、所需工具／容器；明确买几份与实际用多少的区别。原文未提供的量不编造；核心用量不明则待补证。若通过项目试做补全，另记试做日期、实际步骤及结果，不能回填成原作者配方。不得依赖未确认的店员特殊制作、赠送杯碗、免费酱料或拆卖肉饼。
5. **原料能同时获得。** 标出早餐等固定供应时段和与甜品等商品的时段交集。常规早餐不是时令食品，可以收，但不能默认全天供应。门店、配送／自取限制要保留。自备糖、胡椒等调味料必须明示来源与数量；需要外购的主食或核心原料不进入首版麦当劳可操作主库。
6. **来源可追溯。** 每道吃法记录原帖／报道 URL、作者、日期、地区、阅读状态；每张图记录图片ID、路径、哈希、图片来源、关联吃法ID、权利状态。媒体转述与原帖亲读分开。图片与配方来自不同来源时，必须标明差异，不能把相似图当另一来源精确用量的证据。

上述是资料收录门槛。具体门店当次能买到哪些 SKU 和实际价格，仍在用户要求配置时通过官方 MCP 核实；“常规商品”不保证每店每时刻有货。素材公开使用权是独立的发布门槛，未确认权利的文件只留本地 Git 忽略目录。

## 状态与收集流程

- `lead / 待识别`：只有配图或视觉线索，商品、步骤不全。仅存研究区，不进入可操作吃法池。
- `needs_evidence / 待补证`：已有名称和报道配方，但常规供应、商品、实拍或操作用量等门槛未过。逐项记录缺口。
- `ready / 可操作候选`：上述六项均通过并写明证据；仍未等同于当次门店核验、项目试吃或公开权利获批。
- `excluded / 排除`：明确依赖时令／限时／停供品、缺少合格配图，或关键步骤无法复现；保留排除原因及研究档案，不计入收录数。

收集时先过图片和商品身份，再核非时令及大陆供应，最后整理数量、步骤与同时获取条件。已知不符合的停止扩充；未知的暂存待补证。新增条目不能因为“有图”就自动进入正式可操作库。

## 最少维护字段

- 吃法：稳定ID、整理名称、名称依据、来源URL及地区／日期、证据状态。
- 商品：来源原名、大陆商品候选名、口味／规格、购买份数、实际用量、识别依据、是否需外购。
- 非时令：`regular / seasonal_or_limited / discontinued / unknown`、官方或其他可核依据URL、核查日期与适用地区；未知不能视为常规。
- 操作：步骤、工具、容器、供应时段、同时获取条件、未知项、是否项目试做。
- 图片：图片ID、相对路径、关联吃法ID、成品／过程类型、实拍依据、出处、SHA-256、权利状态。
- 收录：`lead / needs_evidence / ready / excluded`、缺项或排除原因、复核日期。

## 地区商品名统一与核验项拆分

大陆展示名与来源原名必须同时保存。已核实的同类地区称谓可以统一，比如冰炫风→麦旋风系列、蛋卷冰淇淋→圆筒冰淇淋、薯饼→脆薯饼；规格和口味不明必须继续标注。所谓“对应”不保证不同地区配方、大小或风味一致。

柳丁汁可以转写为橙汁，但不能据此指定某款大陆橙味饮品。苹果派不能改成菠萝派，玉米浓汤不能改成玉米杯，奶球不能直接当作牛奶。候选商品必须标“候选”，尚无对应的标“未确认”，不得强行本地化。大陆营养目录未匹配某个名称，也不等于该商品全国不存在或已经停供。

维护时将以下核验项分列：配方完整度、商品名称对应、原料获取与时段、参考门店菜单、非时令属性、图片依据。商品名核验可以利用官方常见餐品营养目录或官方产品页；当次菜单核验须记录门店、渠道、查询时间与商品编码。前者不能冒充后者，也不能证明全年供应。

## 每批采集先核菜单（2026-10-24）

用户进一步要求图片对应商品必须实际核对供应。后续每批收集先建立大陆参考门店的采购词表，再围绕已查到的常规商品收集对应实拍；收集后再次把配方原料逐项映射到真实菜单与必要详情，不以营养目录有名代替菜单核验。

- 记录门店、渠道、实际查询时间、预约查询用餐时间、商品编码；复合商品先展开口味/规格选项，例如“派”“经典麦旋风”，避免漏判。
- 必须分清单品可选项与套餐内可选项；只在套餐内找到的，写明购买约束，不能伪装成能单买。
- 跨早餐/正餐的组合查同一时段能否同时出现；时段活动不得当作全年全天供应。
- 食材未匹配、规格/口味不同、仅有类似候选，默认不进入主要商品匹配图库；酱料和奶球未列出只能记获取未确认，不能宣称餐厅一定不提供。
- 图库默认显示主要商品在已查时段匹配的候选，配方、图片与非时令门槛继续独立核查。纯图片线索和不匹配条目保留在待核研究区，不计为可操作收录。
- 一店一时段菜单不能推出全国缺货/停售或常年供应；换店、换时段、用户真正准备点单时须重新查询。本次核验不授权订单、支付或领取优惠。
